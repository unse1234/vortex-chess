# Security and trust boundaries

This is an implementation inventory, not a security certification. Source audit29 October2026; actual verification and unavailable dependency checks are separated in [testing](testing.md). Deployment requirements in [deployment](deployment.md) are requirements, not claims that a production environment satisfies them.

## Credentials, sessions and recovery

`PasswordService` uses Argon2id, memory65536 KiB, three iterations and one lane, plus a dummy verification path for unknown accounts. Passwords are not trimmed; new password length8–128, login nonempty/max 128. Email normalization is trim/lowercase without provider-specific alias rewriting. Username display case persists with a lowercased unique key; SQL CHECKs/indexes protect concurrent identity writes.

Access JWTs: HS256 only, required signing secret >=32 characters with obvious template values rejected; issuer `vortix-api`, audience `vortix-frontend`, sub/sid/jti and short TTL default 300 sec (max 900). Browser holds access token only in service memory. HTTP guards verify JWT and query unexpired/unrevoked matching AuthSession each request; logout/revocation invalidates access before JWT expiry.

Refresh tokens use32 random bytes and only SHA256 digests in PostgreSQL. Raw values exist in HttpOnly cookies, never user JSON/storage/broadcasts. Cookie path `/`, no Domain; secure name `__Host-vortix_refresh`, local nonsecure name `vortix_refresh`; SameSite configurable. Remembered cookie expiry equals absolute session expiry; ordinary cookie is browser-session scoped. Server session defaults24 h or remembered30 d, never extended by refresh. Rotation uses row locking and retains used digests to detect replay; replay revokes that family. Logout is idempotent for missing cookie and affects only that family. Frontend coalesces refresh and uses same-origin Web Locks; unsupported Web Locks means per-tab coordination and real old-cookie replay can revoke the session. Session generations discard stale responses; BroadcastChannel only sends identity events, not tokens.

Reset credentials also use32 random bytes/SHA256 digest. Raw token is temporarily sealed with AES256-GCM and HKDF-derived key from JWT_ACCESS_SECRET so the outbox can build a link after commit. Mail payload is cleared after settlement/replacement/consumption/expiry; sweep deletes long-expired rows. Changing the signing secret also makes existing sealed unsent links undecryptable and invalidates JWTs. Tokens travel in URL fragments; the frontend reads/scrubs them and posts token in body. Reset page has no-referrer/no-index metadata. Token status never consumes; conditional locked consumption plus password/session/outbox changes commit atomically. Newest issued reset replaces outstanding links; success ends all sessions and sockets.

Forgot-password202 is generic and account limits are silently applied (default 60-sec cooldown/five per hour), plus IP throttle. Issuance is tracked in process after lookup and off-response; crash/failure can lose issuance before outbox commit. SMTP receipts do not prove inbox delivery. Registration does not verify email ownership; known/unknown invitation recipients and username availability intentionally permit bounded account discovery. There is no MFA/OTP/OAuth/password-change-while-signed-in/account deletion API.

## HTTP and socket protections

Exact CORS origins are mandatory; no wildcard/trailing slash/path, and production origins HTTPS. Credentials are allowed with explicit methods/headers. CORS alone is a browser response policy. Cookie-auth POSTs additionally require exact allowed Origin and `X-Vortix-CSRF: 1` even for command-line clients. Bearer domain endpoints do not use cookies for authority and do not require CSRF. Missing Origin is refused for auth mutations. Socket adapter allows missing Origin for nonbrowser clients, rejects unlisted browser Origin for WebSocket as well as polling, and authenticates `auth.token` with session lookup.

Session revocations disconnect same-process sockets immediately; periodic default 60-sec checks catch outside changes/absolute expiry. Game commands have a5-sec session-recheck cache; original handshake JWT expiry alone does not close an established session socket. Channel joins rely on authenticated socket identity/domain authorization plus periodic revocation checking, rather than doing full JWT verification each join. Default bounds:10 sockets/user,20 resource channels/socket,16,000-byte socket messages. There is no per-message command rate limiter (gateways skip HTTP throttler). Rate limits are process-memory/IP, not a distributed deployment control.

Helmet, no-store, x-powered-by removal, JSON16 KiB body limit, strict Zod validation on typed handlers, UUID/path bounds and normalized error responses are applied centrally. Generic500s conceal internal errors; some diagnostic services log database/engine error messages and identifiers. There is no comprehensive structured log-redaction pipeline, audit-log product or evidence of an enforced frontend CSP in this repository. TLS/ingress/body limits at hosting remain operator responsibilities.

## Resource authorization and privacy

Room details/settings/ready/start are restricted to seats/host roles. Invitation link IDs identify, not authorize: intended recipient accepts/declines, sender cancels, only parties read. Wrong account receives a specific no-details403. Username/email invitation resolution authorizes host before lookup; no recipient email appears in public-player/invitation/game/social/leaderboard views. Own session user includes own email. Outbox sender privately resolves recipient email.

Game snapshot/history/manual preview/commands and subscriptions authorize participants; spectators cannot subscribe. Actors cannot supply another user or engine seat. Own move requestId is redacted for the opponent. Server rules/clocks/result calculations are authoritative. Client expected revisions, same-ID fingerprints, DB locks/constraints and commit-before-publication handle races; they are not anti-cheat beyond server legality/ownership.

Discovery searches normalized username prefixes with bounded length/page, excludes self and blocked pairs and omits presence/email. Accepted friends can see online/offline only, without activity/last-seen. Blocks are directional records with symmetric interaction restriction; actor sees only own blocked list. Generic unavailable errors hide block direction. Blocks cancel pending interactions and prevent future pairing/start, while committed games/ratings, history and old inbox records remain. Public rankings can still show blocked players. User-writable moderation/rating endpoint does not exist; `leaderboardEligible` is reserved for administrative data changes.

Notification presentation dedupe/browser audio preferences store nonsecret data in localStorage. They are not authorization mechanisms. Same-origin script injection could still access the memory access token or initiate credentialed requests; HttpOnly does not eliminate that boundary. This task did not perform a penetration or dependency-vulnerability audit.

## External dependencies and deployment gaps

The backend validates untrusted engine JSON/status/move metadata, caps responses, refuses redirects and checks resulting move legality/current revision/clock. Operator-supplied engine URL is trusted configuration; no user endpoint sets it, and no upstream auth credential configuration exists. SMTP supports implicit TLS or required STARTTLS; production forbids disabling the TLS requirement. Outbox provider calls occur after domain commit; crash after SMTP acceptance before SENT persistence can cause duplicate delivery. No exactly-once SMTP claim is made.

Single backend ownership is required: distributed presence, socket routing, command ownership/timers and shared rate limits are absent. Running multiple instances can reset active clocks on each bootstrap. Queue cross-process admission tests do not prove multi-instance application safety.

Known product/security work absent: email verification, real terms/consent audit, account erasure/retention policy, distributed throttling, per-command socket rate limiting, comprehensive security/production-browser checks and automated hosting/CI. Current local unit tests prove only their assertions. [Operations](operations.md#known-gaps-and-source-inconsistencies) records contract/documentation discrepancies without pretending recommendations are implemented.
